# 大客户销售

大单不是放大的小单：周期长、多人参与、真正拍板的人常不在场、买错了还会在同事面前暴露，所以成败主要押在前面的需求调查，以及每次会谈争到的一个具体动作，不在最后的逼单。客户说「再考虑考虑」可能是症状（判断）：先看他同意了什么动作，再往上游查问题有没有被问到足够大。爱尝鲜的早期客户之后要打进主流，办法是只选一个小而具体的细分，集中打，不并行。

## 速览

- **最关键的问题**：这单是不是大单（要多次会谈、多人参与，拍板的人常不在场，买错会被同事看到）？上次会谈结束时，客户同意去做的具体动作是什么，还是只留下了「很感兴趣」「以后联系」？客户说出口的，只是承认有问题，还是已经在谈行动、对方案提具体要求？
- **首选打法**：
  - **先问后讲的需求调查**：按背景—难点—影响—价值四类提问（指导方针，不是脚本），把客户承认的问题问成他自己说出口的明确要求；问出之前别把功能亮点讲一遍，并让联系人用自己的话说出价值。
  - **每次会谈争一个具体动作**：拜访前把目标写成客户要做的一个动作；听到「再考虑考虑」，看后面有没有他同意的动作或时间点，没有就按搁置记（推断；他也可能真是内部流程要时间）。
  - **早期客户之后只选一个小而具体的细分**：先用四个一票否决问题筛，只认一个细分，资源集中打。
- **最常见的坑**：把聊出几个痛点当线索质量，或把「很感兴趣」当会谈成功；对精明的专业采购用假设成交、二选一、最后通牒这类逼单话术（决定越大越招抵触，但完全不推也不行）；背景问题一口气问一长串，影响类提问却太少。
- **证据**：大小单的分野、四类提问和「明确要求预示成交」都来自提出者团队二十世纪八十年代前后的观察，最后一条主要靠一项上千宗大单的研究、没见独立重复；细分选择那半边是咨询公司的长期经验，「只选一个、不能并行」是提出者的断言。
- **不在这张卡里**：听到「再考虑考虑」之后具体回什么话、搁置之后怎么救回来；从零开始怎么拿到第一批大客户会谈（线索、冷启动、约到拍板的人）。

## 先问这几个问题

1. 这单是大单吗：要多次会谈、多人参与，拍板的人常不在场，买错会被同事看到？符合越多，越不能照搬小单话术。
2. 上次会谈结束时，客户同意去做的具体动作是什么？还是只留下了「很感兴趣」「以后联系」？
3. 客户说出口的，只是承认有问题，还是已经在谈行动、对方案提具体要求？
4. 这个问题对他迫切到压得过代价了吗？代价不只是钱，还有买错对他个人的风险。
5. 我不在场时，谁会向老板、财务转述？他讲得出这件事的价值吗？
6. 选主攻细分时：有没有单一、够得着、付得起完整方案的拍板买家？这个问题客户能不能再拖一年？

## 打法

### 1. 需求调查：把客户承认的问题，问成他自己说出口的要求

小单里的开场套路、逼单、逐条驳斥异议，到大单里效果有限，原因在买方处境变了；大单里被问出多少痛点和成败几乎没有联系，看的是痛点后来有没有变成他亲口说出的明确要求。来源没给大小单的金额线，你的产品落在哪边要自己判断。
1. 复盘丢单，先查需求调查有没有问出明确要求，再怪收尾；被说成收尾差的销售，很多次其实是前面没做好。
2. 拜访前写下客户可能有的三个问题（都得是你能解决的），每个下面写难点提问，再顺着难点想它牵出的更严重后果，写成影响类提问。不事先写，影响类提问很难在现场问出来。
3. 现场按背景—难点—影响—价值四类提问推进：背景问题少而有目的；难点提问找不满；影响类提问把后果一层层问大；价值类提问让客户自己说出解决后的好处。这是指导方针不是脚本，客户一开口就给出明确要求时可以直接问价值类。
4. 影响类提问放大的应当是客户自己说得出的真实后果，不替他假设（来源示例里的数字都是客户报的，这条是对示例的补充）。对出钱拍板的人它尤其管用；对使用者，简单问些难点问题通常就有积极效果；连问太多会让人沮丧，之后转到价值类。
5. 价值类提问别太早，也别用在你满足不了的需求上，那时转去谈解决办法。
- 做到什么程度算完成：客户开始自己谈行动、对方案提具体要求，而不只是点头认可问题。谈行动这一信号只来自一位销售的访谈，也可能只是客套。

### 2. 先问后讲，让联系人替你在场外说

大单里成败更多取决于参与者彼此怎么推销，主要部分很可能发生在你不在的时候；联系人转述自己的需求，比转述你的产品靠谱。
1. 问出明确要求之前，别把功能亮点讲一遍：针对客户已说出要求的陈述才跟成交紧密相关，泛泛的好处对大单帮助很小，还会随会谈轮次衰减。新品上市同理，先弄清它能解决哪些客户的什么问题。
2. 客户一上来就要你介绍产品，会前先找其中关键的一位聊聊，让介绍里有一部分对准他的需求。客户确实要功能细节时（如复杂高科技产品的技术人员），照给。
3. 用价值类提问让联系人用自己的话说出哪部分对他最有帮助；别把方案讲成什么都覆盖，那等于请客户把所有要解决的方面都列出来。
4. 他说要回去向财务或老板提某件事，就追问对那些人的好处；示例里买方因此说出了更重要的原因，还答应设法约总经理谈一刻钟。

### 3. 每次会谈争一个具体动作，听到「再考虑考虑」先看动作

研究里把会谈结果分四种：成交；推进了一步（同意参加演示、让你见更高一级的人、试用或检测、先接受一部分原先不接受的预算）；搁置（生意还在，客户却没同意任何具体动作，常以「以后联系」收尾）；明确拒绝。搁置算不成功，看客户的行动，不看他的话。
1. 拜访前把目标写成客户要做的一个动作，比如来厂里讨论、约你见他老板。「了解需求」「建立关系」可以顺带做，但只写这两样，结果多半是搁置。
2. 结束前依次做：问还有没有我没解释的疑虑；把几小时的内容聚成他得到的利益；最后用建议的口气提下一步，不用请他签字的口气。
3. 提议的下一步要同时满足两条：真能让生意向前；是客户现实中最多能给的，别超过他承受得起的。
4. 客户说「再考虑考虑」，看后面有没有跟着他同意的动作或时间点。来源没有逐字归类这句话，这是用上面的判据推出来的：没有就按搁置记，哪怕气氛很好；他也可能真是内部流程要时间，所以看动作，不看语气。
5. 你提了具体下一步而他拒绝（不肯再开会、不让你见更高一级的人），已接近没成。
6. 「再考虑」成了常态，往上游查（判断）：天平一端是迫切程度，一端是代价；没倾斜时，多讲产品细节多半无济于事，加压可能更糟。把这句话对应到失衡是推断。
- 做到什么程度算完成：每次会谈结束，你都能写出一句「客户同意了＿＿」；写不出，就记作搁置。

### 4. 早期客户之后：只选一个小而具体的细分

爱尝鲜的早期客户和主流客户的心理画像差别很大，经验外推要非常小心；也不能在两处同时打进去，资源要集中到一个细分里争主导地位。
1. 别拿「这个市场多大、我们拿几个点」壮胆：新细分里你没有经验也没有数据，规模预测背后是多重任意假设。承认缺数据，用具体的客户形象校准直觉。
2. 召集熟悉一线的人，为每个现有客户和有意思的潜在客户各写一页纸场景：用户、技术把关人、出钱拍板的人是谁；用户卡住的一天（情境、想要的结果、现有做法、哪里出错、经济后果）；用上新方案后的一天（新做法、省下的成本或多得的收益）。写到大概二十到五十个会开始重复，归并成八到十个方案。
3. 第一关，四个一票否决问题：有没有单一、够得着、付得起完整方案的买家；不解决的后果是否大到不能再拖一年（主流的务实客户能忍一年的问题就会忍，你的销售会被一再请去演示却拿不回订单）；你加伙伴能否在约一个季度内拿出完整方案；对手是否已先占住（已占住也先看能否绕开）。任何一项极低几乎总是否决，不能只看总分。
4. 第二关，其余几项：伙伴、分销、定价（按完整方案的总价算，并让伙伴有得赚）、定位（起初不被信任是常态，真承诺补齐缺口，抵触可以很快克服）、拿下后能否进入相邻细分。这些低分通常能靠投入和时间补上，只是投入和时间最缺。
5. 规模与自己体量相称：想被主流客户当作标准，得拿下该细分下一年新订单的至少一半。太大就沿口碑圈子的边界切小，太小就并入真实的上位细分，找不到合适的上位细分，多半该回头另选；来源的算例是假设数字；这里只做数量级核对（判断，来源没有调和它与前面别拿规模预测壮胆这一条）。
6. 定案：一个尽量小、但包含所有能否决结果的人的小委员会，先各自私下打分，再公开讨论分歧，第一关通常淘汰约三分之二。三种结局：一致就推进；定不下，让一个人把候选按「拿下它能带动哪个相邻细分」排成一线，先打打头的；无一幸存，就别硬去跨、也别求增长，继续接早期客户的项目，压低烧钱率，继续找。
7. 定了就全力投入，不必选到最优，要赢下选中的这个；调研早做、专门验证获胜场景的前提，但不等结果才动手。
- 做到什么程度算完成：团队只认一个细分，并且它过了四个一票否决问题。

## 常见的坑

- 把聊出几个痛点当线索质量，或把「很感兴趣」当会谈成功：提出者多次见到客户用礼貌的肯定话体面送客。
- 对精明的专业采购用假设成交、二选一、最后通牒这类逼单话术：决定越大越招抵触，还可能拉低购后满意度。但完全不推也不行（小单数据里一次都不推，成功率更低），要换的是推进方式。
- 背景问题一口气问一长串（有场会谈问了三十五个背景问题、其余为零，被买方请了出去），影响类提问却太少，研究里二十个问题只有一个。

## 两派看法

**一派：用提问把客户眼里的小问题问大。** 客户承认问题却觉得能凑合时，顺着后果一层层问，直到他自己觉得值得行动。
**另一派：直接挑购买理由本来就强的细分。** 主流客户觉得问题还能再忍一年就会忍。
怎么选（判断，来源没有调和）：两者管不同层次，后者管去哪个细分，前者管单子里怎么让客户看清代价。选细分先用后者筛；细分里问题本来就小，靠提问放大的空间有限。

**一派：同意参加演示算推进。**
**另一派：购买理由不够强时，主流客户会一次次请你演示，却不下订单。**
怎么选（判断）：每一步都该把你推近真正拍板的人；连着对同一批人演示、没有更高层或试用或预算跟上，按重复的搁置记。

## 什么时候这套不管用

- 小单（一个电话或自助下单就能定）：传统话术仍可用；低价、客户不精明、不必长期维系时，逼单可以很有效；服务类销售里问题反而是要得太少。
- 价格很低时，客户承认问题就足以买。
- 联系人没有影响力，训练他内销收益有限（判断）；团队没人接触过目标客户，一页纸场景只是想象（判断）。
- 消费市场：用户、技术把关人、买单人往往合并成一两个角色，来源说几乎所有成功的跨越都发生在企业市场。
- 样本是二十世纪八十年代前后的企业设备销售；自助试用、订阅制的产品，什么算推进要自己换算。

## 例子

- 一位新手销售见了电信客户，对方认同高峰容量不足、数据质量不满意，他就断定会谈成功；两周后客户在和竞争对手谈，几个月后对手拿下这单。同公司业绩前五的一位说，真正让他觉得有戏的是客户开始谈明年要做什么。这是两位销售的访谈，不是统计。
- 一位高级销售想请客户的总工程师来厂里谈可行性；对方没来，他却在会上发现客户刚得到建新厂的机会，当场请对方约一位相关工程师，拿到了见面日期。上司说他收尾厉害，提出者陪了几次拜访，没见他用过逼单话术：在提出者看来，他靠的是拜访前怎么设目标，这只是一个人的案例。

## 证据有多硬

- 大小单的分野、四类提问的顺序，以及「明确要求预示成交、承认问题不预示」，都来自提出者团队二十世纪八十年代前后的观察，后者主要靠一项上千宗大单的研究，没见独立重复；提出者自己也说四类提问只是把有经验销售已在做的事描述得更精确，也说不太明白泛泛好处为何随会谈衰减。需求调查影响最大这条只依据文字结论，没见到量化图表；各步骤的分量也因生意而异。
- 价值等式（迫切程度对代价）是用图示和例子表达的定性框架，没有度量办法；示例对话是提出者的小例子，不是实测记录。
- 逼单话术失灵：几项研究各有缺陷，提出者自己也承认；直接测过的贵重货品平均才一百来美元，几千几万的大单是推断。方向可信，力度存疑。
- 四种会谈结局是研究的记分规则，不是对客户心理的判决；客户同意的动作也可能只是客气，这一层没人核对。药品公司实验组首年多卖约一半，是提出者自家实验，设计没交代，只当方向参考。
- 收尾几步和把目标写成客户的一个动作，是提出者对高效销售倾向的定性概括，没有分步效果数据。
- 细分选择那半边是提出者那家咨询公司的长期经验：只选一个、不能并行是他的断言；打分主观，后三项没给打分口径，能否带动相邻细分是对未来的判断；场景材料含虚构和偏见，没有检验检查表预测力的数据；至少拿下一半新订单是经验断言；直觉比分析可靠只有类比和咨询经验为据，适合数据缺位时当做法，不是通则；定了就投入、不等调研，靠「拖得越久越利于在位者」论证，没有数据，与先小范围验证再推广的常识有张力。

## 一页清单

- [ ] 判断过这单是大单还是小单
- [ ] 每次拜访前，目标写成客户的一个动作
- [ ] 会前写了三个潜在问题、难点提问和影响类提问
- [ ] 复盘只问三件事：客户同意了什么动作？说的是问题还是行动？问题被问大了吗？
- [ ] 联系人能用自己的话讲价值，我没有在问出明确要求前先把功能讲完
- [ ] 选细分：四个一票否决问题都过了，只认一个，规模与自己体量相称

## 这张卡没覆盖的

- 听到「再考虑考虑」之后具体回什么话，搁置之后怎么救回来、跟进节奏、什么时候放弃
- 客户提出异议时怎么处理（来源只说好销售重在事先防范，没有展开）
- 拿下第一个细分之后，怎么一个个扩张到相邻细分
- 定价、折扣、预算、采购流程、招标、试点怎么设计、合同谈判
- 从零开始怎么拿到第一批大客户会谈：线索、冷启动、约到拍板的人
- 多个利益相关方怎么找齐、拉通，怎么保住那个拍板的买家
- 自助试用、订阅制、产品驱动增长这类现代做法怎么套
- 创始人兼任销售时怎么取舍：招谁、怎么考核
